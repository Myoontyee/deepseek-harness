# Agent Note: 定制应用签名更新渠道

Status: implemented

[English](2026-10-15-custom-update-channel.md) | 中文

## Problem

定制版用户需要反复寻找安装包并手动安装。官方更新源不能代表保留的定制补丁，仅依赖可变的未签名清单也无法独立确认安装包来源。

## Decision

定制包固定 Ed25519 验签公钥及公开 GitHub 更新地址，只有本机保存的私钥能够签署发布清单。验签器拒绝未知字段、无效签名、重复平台、文件名不匹配及不支持的架构；下载地址由固定仓库和不可变版本构造，不信任远程提供的任意 URL。Windows 复用既有 NSIS 更新器与任务感知的重启确认；macOS 校验并下载 DMG，再引导到 Finder，不停止当前应用。保留既有强制更新策略。

本机发布流程在 Android 签名和资源验证后签署更新清单，先公开不可变发布资源，再推进可变更新指针，拒绝版本回退。客户端自动下载通过验证的新版本，仅在窗口可见且任务空闲时提示安装；同一版本的提示被关闭后不反复弹出。

## Alternatives considered

在客户端嵌入 GitHub 令牌会不必要地分发凭据。未经认证的校验文件不能建立独立的发布信任。通过自定义脚本替换未签名 macOS 应用，会将安装范围扩大到平台既有机制之外。

## Consequences

旧版需要手动安装一次引导版本。私钥留在所有者本机并需要本地备份，云端构建在本机签名完成前保持草稿。Windows 包仍无 Authenticode 签名，macOS DMG 仍未签名和公证。更新清单签名认证元数据和文件哈希，不代表操作系统认可的发布者身份。重启仍提醒用户保留未发送的注释草稿。
