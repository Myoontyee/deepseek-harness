# DSH Android Companion

[English](README.md) | 中文

用于桌面版“手机控制”入口的个人安卓版。这不是 DeepSeek 官方安卓客户端。电脑和 DSH 必须保持运行。需要 Android 8.0 或更高版本，建议更新 Android System WebView。

## 连接

1. 安装手机 APK，以及包含“手机控制”入口的对应定制桌面版。
2. 手机和电脑连接同一局域网，或已经配置好的 Tailscale 等私有网络。在桌面版打开“应用 → 手机控制”，选择手机能够访问的私有地址。程序不会自动配置公网转发或安装 Tailscale。
3. 选择“配对手机”，复制五分钟内有效、只能用一次的配对码，粘贴到安卓应用；然后在电脑上确认请求配对的设备。
4. 手机打开同一套 DSH 会话，可以发送任务并处理原有权限确认。已接受的工作在电脑执行。网络恢复后可以点击“重连”。
5. 在电脑的手机控制面板撤销设备，会立即关闭该设备的 HTTP 流和 WebSocket 连接。安卓端清除连接只删除本机凭据；离线时要撤销电脑上的授权，仍需使用电脑面板。

## 身份验证与保存

配对码包含私有网络地址、SHA-256 证书标识和随机一次性密钥。原生配对与 WebView 请求必须匹配该证书并通过有效期检查；电脑身份改变后需要重新配对。不存在通用证书错误放行，也不提供 JavaScript 调用原生功能的桥接接口。内置页面只访问已配对来源；用户主动点击的外部链接可以在系统浏览器打开，不携带 DSH 设备 Cookie。

桌面版通过 Electron 的系统加密保存 TLS 私钥及每台设备的授权摘要，DSH Host 内部凭据只留在电脑。安卓版使用 Android Keystore 的 AES-GCM 密钥加密保存连接，关闭备份，使用 Secure/HttpOnly 设备 Cookie。配对必须由电脑本地批准。此授权允许完整的已认证 DSH 操作界面，包括查看对话、发送和停止任务、处理权限确认，并非只读授权。最多配对八台设备。

## 构建

使用 JDK 17、Android SDK 35、Build Tools 35.0.0 和 Gradle 8.11.1。在不提交的 `local.properties` 中配置 SDK。设置 `DSH_ANDROID_KEYSTORE` 和 `DSH_ANDROID_STORE_PASSWORD`，指定私有且长期保存的签名库，别名为 `dsh-companion`，再运行 `gradle :app:assembleRelease`。禁止提交密钥或密码。后续升级应使用同一签名密钥。分发前运行 `apksigner verify` 验证 APK。

## 验证与限制

发布 APK 已编译并验证安装签名，尚未在安卓真机测试。电脑端网络检查覆盖一次性及过期配对、来源验证、凭据隔离、授权持久化、WebSocket 往返和 HTTP/WebSocket 活动连接撤销。浏览器整体验证与安卓实机验证是不同的验证范围。

当前没有后台推送、手机语音输入、屏幕和鼠标远程桌面、网络唤醒、公网中继或持久化远端 SSH Agent。关闭手机不会主动停止已接受任务，退出 DSH 则停止访问。程序不会自动阻止电脑休眠。电脑所选网络地址变化后，需要选择新地址并重新配对。页面摄像头和麦克风请求会被拒绝，文件选择器仍需实机验证。
